# 技术决策日志（DECISIONS）

> 按时间倒序追加。每条记录：决策 / 备选方案 / 理由。接手者请先读这里避免重新争论。

## 2026-09-27 · 初版架构

### D1 双文件合并策略：ASA 与 IMP 直接并集（而非 IMP 覆盖 ASA）
**决策**：两文件直接并集入库，`source` 字段标记来源；报告优先展示 ASA 实测。
**理由**：实测验证两文件**严格互补**（抽样 19 位点按 rsID+位置均无交集；
总和恰为 5,466,295）。未来若出现重叠，`INSERT OR IGNORE` + 查询时 ASA 优先已兜底。

### D2 存储选 SQLite 而非 Parquet/纯文件
**决策**：单个 SQLite（rsid、chrom+pos 双索引）。
**理由**：零依赖（Python 标准库）、单文件、点查+范围查都快、任何接手者秒懂。
546 万行仅约 300MB，构建 15 秒。Parquet 需要引入依赖，纯 TSV 查询慢。

### D3 原始大文件不入 Git；派生数据入 Git
**决策**：`data/raw`、`data/local`（SQLite）gitignore；`site/data/`（报告 JSON +
按染色体 TSV.gz，共约 20MB）全部提交。
**理由**：①GitHub 100MB 单文件限制（IMP 解压后 117MB）；②原始文件是最敏感资产，
留在本机；③静态站部署需要产物在仓库里（Pages Git 集成无构建机依赖）。
按染色体分文件（最大 ~2MB gz）满足 Pages 单文件 25MB 限制。

### D4 每个面板位点强制 dbSNP 校验（正链等位基因 + GRCh37 位置）
**决策**：`fetch_dbsnp.py` 拉取 NCBI refsnp API，缓存 JSON 提交到仓库；
`verify.py` 比对；不匹配时网站降级展示并打 ⚠️。
**理由**：gesedna 的 rsID↔位置映射存在个别错误；文献大量使用"基因方向"写法
（如 VKORC1 -1639G>A 在正链是 T>C），是单位点解读最大的错误来源。
实测发现 dbSNP 多等位记录（如 rs9923231 正链 C→A/G/T）会让"数据基因型非法"
的假警报变多，因此校验采用"数据等位基因 ⊆ dbSNP 等位基因集合"。

### D5 解读内容写成「面板 JSON」而不是代码
**决策**：`pipeline/panels/*.json` 每条目含三基因型解读（label/text）+ 证据 + 置信度。
**理由**：内容与逻辑分离；非程序员（或未来 AI）改内容不用读代码；
diff 友好；JSON 可被校验脚本检查完整性（interp 键 vs dbSNP 等位基因）。

### D6 报告模块按可靠度排序，并明确「不推断清单」
**决策**：药物基因组学 > 代谢 > 特质 > 健康风险 > 免疫 > 祖先；
CYP2D6/HLA/5-HTTLPR/BRCA 大片段/ACE I/D/Rh 等明确不推断。
**理由**：消费级芯片 + 填充数据的边界。宁可留白不可编造，是本项目科学信誉的核心。

### D7 不做 PRS 与祖源百分比（v1）
**决策**：ROADMAP 中列为后续，需要东亚参考面板。
**理由**：PRS 欧洲系数套东亚误差大；祖源百分比伪精确。见站内祖先模块说明。

### D8 前端零依赖 SPA（vanilla JS + hash 路由）
**决策**：无框架、无构建、无 npm。
**理由**：Pages 零配置；接手者无需前端工具链；报告页交互需求简单（渲染 JSON）。
未来若需要复杂交互再引入框架（见 ROADMAP）。

### D9 用户前期人工清单的用法：交叉校验集 + 关联表数据源
**决策**：8 份清单全部入库比对（结果 494/494 一致），其位点渲染成 5 张关联表，
不硬解读，注释只收录证据充分条目（annotations_curated.json），其余显示"—"+外链。
**理由**：关联级位点效应量小且部分注释易编造；表格 + 外链 + 置信度标签是诚实展示
与"尽可能全"之间的平衡点。

### D10 关联表"待核"条目保留在表中而非删除
**决策**：无法确认基因/表型的位点显示"待核"+⚠️（位置与 dbSNP 不符）。
**理由**：保留完整清单供后续核对（ROADMAP 有"注释补全"任务），删除会丢信息。
